# API 합의: <feature>

[English](_template.md) | [한국어](_template.ko.md)

공통 API 결정·인계에만 사용한다. 백엔드·앱 구현 메모는 소유 영역의 `docs/features/`에 두고 한 작업에 양쪽 구현을 요구하지 않는다.

## 가치와 계약

- 계약 상태(`Draft` / `Agreed`), app·backend 검토 근거, 인계받은 앱 흐름에서 확인한 데이터 요구:
- 사용자 가치와 요청 영역:
- 루트 SDL 경로, Query/Mutation, 입력·출력 필드·nullability:
- SDL 설명에 기록할 정상·빈/false 데이터·검증·오류 의미:
- 호환성 영향, 변경 제안, 합의한 결정:

## 인계

- 계약 diff와 예상 요청·응답·오류 예시:
- 현재 영역 검증 증거와 날짜/환경:
- 남은 백엔드 작업·앱 모델/fixture 조율·Apollo/adapter 연결, 담당 영역, 통합 검사:
- 필요 시 호환성을 깨는 변경의 전환·배포 계획:

계약 기록은 두 번째 SDL 원본이나 소비 코드 호환성 증거가 아니다. 상대 구현을 읽어 빈 부분을 채우지 않는다.
