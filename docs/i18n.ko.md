# 제품 국제화(i18n)

[English](i18n.md) | [한국어](i18n.ko.md)

이 문서는 이 템플릿으로 만드는 기능의 제품 언어 정책이다. Markdown 번역은 `sync-docs`가 별도로 담당한다. 제품 기본값과 자기 역할의 절을 읽으며 이 정책이 역할 경계를 넓히지는 않는다. 명시적으로 승인된 제품 요구가 있으면 기본값을 바꿀 수 있고, 예외를 기능 기획에 기록해 다음 단계에도 인계한다.

## 제품 기본값

- 하나의 앱에서 한국어(`ko`)와 영어(`en`)로 같은 기능을 제공한다. 새로 만들거나 바꾸는 사용자 흐름은 두 언어를 모두 지원하며 기존 제품을 수정할 때 관련 없는 현지화 누락은 별도로 기록한다.
- 지원하는 OS의 앱별 언어 선택을 포함해 플랫폼의 언어 결정 방식을 따른다. 사용자의 언어 선호 목록 순서에서 지원 언어를 찾고, 일치하는 언어가 없으면 영어를 사용한다. 국가·SIM·시간대가 아닌 언어 태그로 언어를 선택한다. 기능 범위에서 요청하지 않으면 앱 내부 언어 선택 화면을 추가하지 않는다.
- 앱이 소유한 라벨·Navigation·대화상자·검증/오류/재시도/빈 상태 문구·접근성 라벨/힌트·권한 설명을 포함한다. 승인된 브랜드명과 사용자 작성 콘텐츠는 유지하며 의도적으로 번역하지 않는 문구를 명시한다. OS가 소유한 안내는 OS를 따른다.
- 번역은 의미·동작·말투·자리표시자를 보존한다. 대체 언어는 미지원 언어에 대비한 것이지 누락된 한국어·영어 번역의 완료 증거가 아니다. 날짜·숫자·수량·금액은 플랫폼의 로케일 기능으로 표시하며 언어만 바뀌었다고 저장된 값·시간대·통화를 바꾸지 않는다.

## 기획

기존 기능 기획에 지원 언어, 대체 언어와 언어 선택 동작, 콘텐츠 예외, 두 언어의 관찰 가능한 완료 조건을 기록한다. 기능마다 다시 묻지 말고 기본값을 상속한다. 현지화된 원격 콘텐츠나 로케일에 따라 달라지는 비즈니스 규칙이 있으면 나중의 계약 인계 대상으로 표시하며, 기획에서 리소스·API·저장 방식을 선택하지 않는다.

## 디자인

접근성 콘텐츠를 포함한 각 상태의 한국어·영어 문구를 기존 디자인 기록 또는 참조된 디자인에 제공한다. 같은 Figma 파일/페이지에 시제품 화면의 두 언어 버전을 보여준다. 기존 승인은 재사용하고 한정된 수정은 전체 디자인 흐름을 재시작하지 말고 영향받는 상태를 검토한다. 텍스트에 영향을 받는 화면은 언어별 변형으로 한글 글리프·행간·줄바꿈·긴 영어 라벨·작은 화면·글자 확대를 확인한다. 공통 레이아웃/컴포넌트는 공유하며 언어만을 이유로 제품 파일이나 Design System을 나누지 않는다.

실제 문구 원본, 번역 검토 상태, 승인된 예외, 언어별 화면 증거를 인계한다. 번역 초안과 검토된 문구를 구분한다. Figma 승인만으로 실행 중 언어 선택이나 리소스 커버리지가 확인되는 것은 아니다.

## 앱 개발

KMP의 Domain/Data/Network 경계에 맞춰 현지화는 네이티브 Presentation에 둔다. 프로젝트의 기존 네이티브 현지화 방식을 재사용하고 새 템플릿 기반 앱에서는 다음 기본값을 사용한다. 이는 구현 지침이며 해당 파일이 이미 존재한다는 뜻이 아니다.

| 플랫폼 | 리소스와 사용 정책 |
| --- | --- |
| Android / Compose | `res/values/strings.xml`에 완전한 영어 기본값, `res/values-ko/strings.xml`에 한국어를 두고 Compose에서 네이티브 문자열/복수형 리소스를 사용한다. OS 앱별 언어 선택을 위한 지원 언어를 설정하고 두 번역이 패키지에 포함되는지 확인한다. |
| iOS / SwiftUI | 영어 원본/개발 언어와 한국어 번역이 있는 String Catalog(`Localizable.xcstrings`)를 사용한다. 적절한 기존 `.strings`/`.stringsdict`가 있으면 관련 없는 리소스를 마이그레이션하지 말고 재사용한다. 대상 앱 포함 설정, 지원 언어, 개발 언어, 앱 소유 권한 설명의 현지화를 확인한다. |

각 메시지는 문맥을 담은 안정적인 리소스 식별자를 갖고 필요하면 번역자 설명을 제공한다. 의미가 같은 메시지는 재사용하되 영어 철자만 같은 별개 메시지를 합치지 않는다. 보간·접근성 문구를 포함한 사용자 문구는 네이티브 현지화 리소스/API에 연결한다. 현지화 API에 전달하는 SwiftUI 리터럴은 추출과 두 언어 번역을 확인하면 허용하지만, 현지화를 우회하는 표시 문자열이나 동적 문자열은 허용하지 않는다.

타입이 있는 자리표시자와 플랫폼 복수형 규칙으로 완전한 메시지를 표현한다. 번역 조각을 이어 붙여 문장을 만들거나 두 언어에 같은 복수형 범주를 강제하지 않는다. 번역 간 타입과 인자 식별을 일치시킨다. 번역된 UI 문장이나 자체 번역 엔진을 Shared에 넣지 않는다. 타입으로 구분한 실패를 네이티브 UI의 현지화 메시지에 매핑하고 알 수 없는 실패에도 안전한 현지화 기본 문구를 제공한다. 서버/디버그 오류 원문을 사용자에게 표시하지 않는다.

## 계약과 백엔드 인계

UI 문구 번역만으로 GraphQL이나 백엔드를 바꿀 필요는 없다. 프로토콜 식별자·enum 값·오류 코드·저장하는 기계용 값은 언어와 무관하게 유지한다. 서버가 현지화된 콘텐츠를 제공한다면 요청된 계약 단계에서 언어 협상·지원 언어·대체 언어·응답/오류 의미를 합의한 뒤 의존하는 구현을 진행한다. 서버가 생성하는 사용자 문구와 알림이 범위에 포함되면 별도의 백엔드 현지화 책임으로 기록한다. 앱 fixture로 서버 언어를 추정하거나 임의의 서버 문구를 실행 중 번역하지 않는다. 각 역할은 합의된 계약을 사용하며 자기 구현 영역 안에서 작업한다.

## 검증과 완료

영향받는 UI/리소스에 대해 앱 역할이 기능 기록에 다음 검사를 남기고 디자인은 제공된 렌더링을 검토한다. 요청된 영역 안에서 기존 플랫폼 검사와 관련 테스트를 사용한다.

1. 영향받는 메시지의 `ko`/`en` 번역이 완전하고 검토됐는지 확인한다. 자리표시자·복수형·접근성·권한 문구·의도적 예외를 포함한다. 누락·빈 값·리소스 키 노출·검토하지 않은 대체 문구는 완료가 아니다. 파일 존재뿐 아니라 네이티브 리소스 추출과 패키징도 확인한다.
2. 각 대상 플랫폼에서 영향받는 흐름을 두 언어로 실행한다. 성공과 관련 빈 상태/오류/재시도, 보간과 복수형 수량, 로케일별 표시, 글자 확대, 줄바꿈, VoiceOver/TalkBack을 확인한다. 증거는 플랫폼·언어별로 기록하고 실행할 수 없었던 검사는 미검증으로 표시한다.
3. 언어 결정과 변경을 확인한다. 한국어·영어 선호, 미지원 언어만 있을 때 영어 대체, 미지원 언어 다음에 지원 언어가 있는 선호 목록을 검사한다. 지원 OS에서는 앱별 언어 선택과 플랫폼에 필요한 갱신/재실행 뒤의 화면을 확인한다. 앱 내부 선택기가 실제 범위에 있을 때만 그 설정의 저장 여부를 검사한다.
4. 영향받는 플랫폼 빌드/테스트를 실행하고 네이티브 현지화 진단을 확인한다. 기존 `./tools/verify.sh app`과 `./tools/verify.sh ios`만으로 두 언어의 UI 동작이 증명되지는 않는다. `./tools/verify.sh structure`는 저장소/문서 구조 검사이며 앱 번역·화면 검사가 아니다. 완료한 검사와 남은 플랫폼·언어별 미검증을 나눠 보고한다.
