# App rules

[English](AGENTS.md) | [한국어](AGENTS.ko.md)

Scope: `app/` (Shared, Android, iOS), its documentation, app tools/configuration, and the root `contracts/graphql/` contract drafts this scope owns. Do not read Go resolvers, repositories, DB schema, or backend docs to infer app behavior. Consume the SDL and its descriptions; report contract gaps instead of guessing or implementing the server.

- KMP shares Domain/Data/Network only. No Compose, SwiftUI, ViewModel, navigation, or screen state in `shared/`. Android uses Compose/ViewModel; iOS uses SwiftUI/native `@Observable` state.
- Use consistent feature names across Shared and Android `feature/<domain>` and Swift `Features/<Domain>`. Before a contract exists, derive names from approved product concepts and reconcile them at contract settlement. Use short singular lowercase names, PascalCase in Swift. Initial feature: `system`; no example business domains.
- For UI work, develop native flows after the design, Design System, and token correspondence are approved; use Make artifacts, existing approved Figma, or an agreed local specification. Contract-only, GraphQL connection, and other non-UI changes enter at their requested stage without a design prerequisite. Use local fixtures/repository test doubles for working screens, navigation, state, and local behavior before a new API contract exists; mark data and remote behavior assumptions as provisional. A missing contract does not limit app work to scaffolding. Reuse an existing contract and contract-aligned Mocks when applicable.
- After app flow validation, draft needed root SDL changes in the requested contract step from demonstrated data requirements. The backend scope reviews implementability and settles the contract with app before server work. After agreement, align app models/fixtures, update app-owned Operations, regenerate Apollo, and wire GraphQL adapters. Apollo reads root SDL directly; generated Kotlin stays in build outputs. Backend implementation and DB changes are not app work.
- For UI, use approved Make artifacts, existing approved Figma designs, or an agreed local specification with the Design System reference; reuse native components and `design/design-system-map.yaml` Tokens. Token matching precedes app development and needs no GraphQL approval. Implement planned native symbols before recording actual mapping exceptions. Keep semantic colors, typography, spacing, and radii in the Design System.

Use [develop-app](../.agents/skills/develop-app/SKILL.md) and [app docs](docs/index.md). Run `./tools/verify.sh app` for Shared/Android and `./tools/verify.sh ios` for Swift/Apple interop, plus affected platform tests and actual UI/accessibility review. Shared changes may require both app platforms; they do not require backend tests. Distinguish provisional fixture, contract-aligned Mock, and live endpoint evidence; model relevant nullability, errors, and cancellation. Mocks do not prove server compatibility. After backend delivery, complete requested connection checks against the provided endpoint; full server/app integration is a separate explicitly requested task.

Design-only tasks use [design rules](design/AGENTS.md) and [design-app](../.agents/skills/design-app/SKILL.md); they produce a design handoff without implementing or building the app. The app role implements an approved handoff and reports new design decisions to design.
